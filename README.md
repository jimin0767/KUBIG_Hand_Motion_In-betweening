# 키프레임 기반 손 동작 생성(Hand Motion In-betweening)

KUBIG Summer Contest DL 3팀 — 키프레임 기반 손 동작 생성(Hand Motion In-betweening)

---

## 1. Motion In-betweening 태스크란

**Motion in-betweening**은 애니메이션 제작에서, 애니메이터가 배치한 **키프레임(keyframe) 사이의 중간 동작을 자동으로 채워 넣는 문제**야. 전통적으로는 게임/영화 애니메이션 파이프라인에서 "시작 자세"와 "끝 자세"만 정해두면, 그 사이 자연스러운 움직임을 자동 생성해주는 도구로 연구돼 왔어.

### 표준 문제 정의

- **컨텍스트(context)**: 과거 몇 프레임(관측됨)
- **목표 키프레임(target)**: 미래의 한 시점, 이미 정해진 자세(관측됨)
- **전이 구간(transition/gap)**: 컨텍스트와 목표 사이, **모델이 채워야 할 프레임들**(미관측)

### 연구 계보

| 논문 | 핵심 기여 |
|---|---|
| RTN (Harvey & Pal, 2018) | 딥러닝 기반 in-betweening 최초 시도 |
| **RMIB** (Harvey et al., 2020) | LaFAN1 벤치마크 도입, **time-to-arrival(ztta) 임베딩**으로 목표까지 남은 거리를 인코딩 — 이후 계보 전체의 표준이 됨 |
| CMIB (Kim et al., 2022) | Transformer 기반 최초, BERT 스타일 마스킹 |
| Two-stage Transformer (Qin et al., 2022) | Context+Detail 2단계 구조 |
| Delta-Interpolator (Oreshkin et al., 2023) | 보간값 대비 잔차(delta) 예측 |
| **SILK** (Akhoundi et al., 2025, EA SEED) | **단일 인코더로 단순화**, 이 프로젝트의 백본 |

**우리 프로젝트가 이 계보에 접목한 지점**: 지금까지 이 분야는 full-body 애니메이션에 집중해 왔고, **손 전용으로 다뤄진 연구는 확인된 바 없어** — 이 프로젝트는 이 태스크를 손 관절 시퀀스에 도메인 전이한 시도야.

## 2. SILK 모델

**논문**: Akhoundi et al., 2025 (arXiv:2506.09075), EA SEED. **공식 코드 없음** — 논문 설명을 바탕으로 전 과정을 직접 재구현.

### 핵심 설계

- **단일 Transformer 인코더**만 사용 (이전 연구들의 다단계/다중 인코더 구조를 단순화)
- 스펙: **6층, 8헤드, d_model=1024, d_ff=4096**, Pre-LN, GELU
- 입력 구성: `컨텍스트(C=10프레임) + 전이구간(M=5~30프레임, 0으로 채움) + 목표 키프레임(1프레임)`
- **손실**: 전체 시퀀스에 대한 단일 L1 (마스킹된 gap 구간만이 아니라 전체)
- 학습 시 M(가림 길이)을 매번 [5,30] 균일 무작위로 뽑음(RMIB의 원래 커리큘럼 방식을 SILK가 단순화한 것)
- **위치 인코딩**: 목표 키프레임을 기준(상대위치 0)으로 하는 학습형 임베딩 — RMIB의 time-to-arrival(ztta) 설계와 개념적으로 동일. 이 설계를 정확히 재현하지 않으면(예: 단순 절대 위치 임베딩), **목표/전이 구간의 위치 정체성이 M에 따라 충돌하는 confound 버그**가 생긴다는 걸 프로젝트 초기에 직접 발견·수정함 (이 수정으로 학습 수렴 속도 약 10배 개선을 확인).

### 프로젝트에서의 활용

이 팀은 SILK 구조를 **손 관절 회전 시퀀스**에 그대로 적용해 baseline을 구성했고, 이후 각 팀원이 이 백본을 출발점 삼아 서로 다른 방향(모델 확장, 손실 함수 변형, 다중 키프레임, diffusion/flow matching 재구성 등)으로 실험을 확장했어.

## 3. 우리의 Hand Motion In-betweening 태스크

### 왜 손이 특수한가

기존 motion in-betweening 연구는 **전신 동작**을 다뤄. 걷기처럼 몸 전체 위치(root)가 시간에 따라 크게 이동하는 경우가 많아, 시작·끝 자세만 봐도 "무슨 일이 일어났는지"에 대한 강한 단서가 있어.

**손은 근본적으로 다른 구조야**: 손목(root)을 기준으로 정규화하기 때문에, **"손이 벌어졌다가 다시 오므려진" 것과 "아무 일도 없었던 것"이 시작·끝 관측만으로는 구분이 안 되는 경우가 많아.** 이건 문헌상 **"multimodal ambiguity"**로 알려진 문제이고, 결정적(deterministic) 회귀 모델은 이런 상황에서 손실을 최소화하려고 "가장 안전한 답(정지)"으로 수렴하는 경향이 있다는 것도 확인됨.

### 문제 설정

```
[컨텍스트 10프레임(관측)] + [gap 5~30프레임(예측 대상)] + [목표 키프레임 1개(관측)]
```

- **입력 표현**: 6D 회전(Zhou et al. Gram-Schmidt 방식), 손가락 15관절 × 6 = **90차원**, 손목 제외
- **응용 프레이밍**: 애니메이터가 배치한 키프레임을 채우는 원래 맥락이 아니라, **손 추적이 일시적으로 끊긴(occlusion) 구간을 복원**하는 문제로 재정의 — 이 프레이밍 하에서는 "정답을 미리 안다"는 가정 자체가 성립하지 않으므로, 평가 시 gap 구간의 정보가 조건에 새어 들어가지 않도록 하는 것이 특히 중요함(아래 4, 5절 참고)

### 손 특유의 함정과 대응

| 함정 | 대응 |
|---|---|
| 6D 회전 → 실제 관절 위치 변환 시 컨벤션(행/열) 오류 위험 | 공식 소스코드(`pose_datasets_lmdb.py`) 직접 확인으로 **행(row) 기준**임을 100% 확정 |
| 왼손/오른손 좌표계 불일치 | `diag(1,-1,-1)` conjugation으로 오른손(WiLoR) 컨벤션에 통일, 공식 메커니즘과 정확히 일치 검증 완료 |
| 시작·끝이 비슷하면 모델이 "정지"로 수렴 | 다중 키프레임 조건화(세그먼트 중간점 노출), diffusion/flow matching 기반 생성형 재구성으로 대응 |

## 4. How2Sign 데이터셋

### 출처

**SignSparK**(ECCV 2026, huggingface.co/datasets/LionelLow/SignSparK_data)가 CSL-Daily/How2Sign/BOBSL 세 코퍼스를 SMPL-X/MANO 회전 파라미터로 가공해 배포한 데이터 중 **How2Sign(미국 수어, 영어 대응)만 사용**. CSL-Daily는 저자가 공지한 미해결 한손(one-handed) 회전 버그가 있어 제외, BOBSL은 스코프상 미사용.

### 스키마

npz 클립당: `language`, `translation`, `gloss`, `segment`(프레임별 라벨), `left_features`(T,90), `right_features`(T,90), `body_features`(T,126), `face_features`(T,56).

- **90차원 = 15개 MANO 손가락 관절 × 6D 회전** (손목 제외 — 손목 회전은 `body_features`에 별도)
- **`segment`**: `0`=수어 아님, `1`=수어 진행 중, `2`=수어 시작 — 공식 소스로 확정된 값
- 관절 순서: `index → middle → pinky → ring → thumb` (frankmocap 공식 문서로 검증)

### 규모

- 원본: train 29,630 클립 / dev 1,650 / test 2,183
- 왼손·오른손 분리 시퀀스 기준: train 약 5.9만 / dev 3,300 / test 4,366
- stride=5 기반 조밀 윈도우 인덱스(팀 공용, offset을 좁혀 데이터를 늘리는 SILK 논문 방식 그대로): **train 약 163만 개 윈도우**

### 공식 전처리 로직에서 확인된 사실 (자체 소스코드 확인)

- **6D→행렬 변환은 행(row) 기준** Gram-Schmidt (공식 소스 주석으로 확정)
- **왼손 flip**은 `diag(1,-1,-1)` conjugation을 통한 공식 지원 메커니즘 (`flip_left_hand` 플래그, 기본은 꺼져 있으나 팀은 명시적으로 켜서 사용)
- **원래 SignSparK 태스크는 우리보다 훨씬 풍부함**: 클립 전체(최대 224프레임)에 걸쳐 각 수어 세그먼트마다 시작/중간/끝 키프레임을 준다 (`generate_keyframes`/`_segment_bounds`). 우리 팀은 SILK와의 구조적 통일을 위해 이를 "컨텍스트+목표 1개"로 단순화했고, 일부 실험에서 세그먼트 중간점을 보너스 조건으로 부분 복원함 — **이는 SignSparK 원 레시피의 완전한 재현이 아니라 의도적 단순화라는 점을 한계로 명시**.

### 알려진 데이터 품질 한계

How2Sign의 SMPL-X 손 피팅은 **단안(monocular) 카메라 기반 단일 프레임 초기화**를 사용해, 빠른 손동작 구간에서 부정확해지는 경향이 있음(2026년 관련 논문으로 독립 확인). 회전 변화가 극단적으로 큰 일부 구간에서 관찰된 부자연스러운 손 모양은, 코드 검증(관절 순서·FK·6D 컨벤션 전부 정상) 결과 **모델의 결함이 아니라 이 데이터 자체의 알려진 한계**로 확인됨.

## 5. 평가 프로토콜

- **split**: train(학습) / dev(개인 검증) / test(팀 최종 비교)
- **평가 지점**: 가림 길이 T = 5, 10, 20, 30
- **지표**:
  - **L2Q**: 부호보정 쿼터니언 L2 거리(더블 커버 문제 처리)
  - **L2P**: MANO forward kinematics로 복원한 관절 위치 오차(팀에 따라 근사 템플릿 또는 실제 MANO 사용, 아래 6절 주의사항 참고)
  - **NPSS**: FFT 기반 파워스펙트럼 유사도(움직임의 리듬/자연스러움)

### diffusion/flow, 생성형 재구성 계열 (신영)

| 실험 | L2Q (T5/10/20/30) |
|---|---|
| 1. 유출 수정(DDPM, 재학습 없음) | 0.0258 / 0.0566 / 0.0919 / 0.1178 |
| 2. 키프레임 고도화(DDPM) | 0.0255 / 0.0516 / 0.0868 / 0.1119 |
| 3. 속도 손실 추가(DDPM) | 0.0276 / 0.0587 / 0.1061 / 0.1372  |

**패턴**: 다중 키프레임 조건화는 이 팀에서도 유효(1→2번 개선). 속도 손실은 이 팀에서도 역효과. **DDPM에서 Flow Matching으로 생성 프레임워크 자체를 전환한 것이 가장 큰 개선**을 가져옴 — SignSparK 원 논문 자체가 Flow Matching을 사용한다는 점과도 방법론적으로 부합.


## 7. 최종 모델 선정 — exp06

### 선정 근거

**exp06(SILK 원 논문 크기, 76M 파라미터, 결정적 회귀)이 L2Q·L2P·NPSS 세 지표, T=5/10/20/30 전 구간에서 가장 낮은(좋은) 오차를 기록**했으며, 3절의 주의사항을 감안해도 격차가 충분히 커서 결론이 뒤집힐 가능성은 낮다고 판단.

### 함께 보고해야 할 해석

- **모델 크기가 이 태스크에서 뚜렷한 성능 요인**임을 3M→19M→76M 스케일업 실험이 일관되게 보여줌
- 보조 손실(다양성/속도) 추가는 양쪽에서 **독립적으로 재현된 역효과** — 신뢰도 높은 부정적 결과로 보고 가치 있음
- 다중 키프레임 조건화는 팀원2·이 팀 양쪽에서 **독립적으로 재현된 긍정적 효과**
- **정확도 지표(L2Q/L2P/NPSS)는 "정답과의 거리"를 재는 방식이라, 결정적 회귀 모델의 "안전한 평균" 예측에 상대적으로 유리하게 작용할 수 있음.** 이 팀의 diffusion/flow 계열은 애초에 이 지표들이 잘 포착하지 못하는 문제(다양성, multimodal ambiguity 완화)를 겨냥해 설계됐다는 점에서, **정확도 1위가 아니라는 결과가 방법론의 실패를 의미하지는 않음** — 정성적 시각화를 통한 보완적 평가가 필요하다는 점을 한계 및 향후 과제로 명시
