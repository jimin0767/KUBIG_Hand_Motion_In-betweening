# 키프레임 기반 손 동작 생성 (Hand Motion In-betweening)

KUBIG Summer Contest DL 3팀

---

## 1. Motion In-betweening Task

**Motion in-betweening**은 애니메이션 제작에서, 애니메이터가 배치한 **키프레임(keyframe) 사이의 중간 동작을 자동으로 채워 넣는 문제**이다. 전통적으로는 게임/영화 애니메이션 파이프라인에서 "시작 자세"와 "끝 자세"만 정해두면, 그 사이 자연스러운 움직임을 자동 생성해주는 도구로 연구되어 왔다.

### 표준 문제 정의

- **컨텍스트(context)**: 과거 몇 프레임(관측됨)
- **목표 키프레임(target)**: 미래의 한 시점, 이미 정해진 자세(관측됨)
- **전이 구간(transition/gap)**: 컨텍스트와 목표 사이, **모델이 채워야 할 프레임들**(미관측)

### 연구 계보

| 논문 | 핵심 기여 |
|---|---|
| RTN (Harvey & Pal, 2018) | 딥러닝 기반 in-betweening 최초 시도 |
| **RMIB** (Harvey et al., 2020) | LaFAN1 벤치마크 도입, **time-to-arrival(ztta) 임베딩**으로 목표까지 남은 거리를 인코딩 — 이후 계보 전체의 표준이 됨 |
| CMIB (Kim et al., 2022) | Transformer 기반 최초, BERT 스타일 마스킹 |
| Two-stage Transformer (Qin et al., 2022) | Context+Detail 2단계 구조 |
| Delta-Interpolator (Oreshkin et al., 2023) | 보간값 대비 잔차(delta) 예측 |
| **SILK** (Akhoundi et al., 2025, EA SEED) | **단일 인코더로 단순화**, 이 프로젝트의 백본 |

**이 프로젝트가 이 계보에 접목한 지점**: 지금까지 이 분야는 full-body 애니메이션에 집중해 왔고, **손 전용으로 다뤄진 연구는 없다** — 이 프로젝트는 이 태스크를 손 관절 시퀀스에 도메인 전이한 시도이다.

## 2. SILK 모델

**논문**: Akhoundi et al., 2025 (arXiv:2506.09075), EA SEED. **공식 코드 없음** — 논문 설명을 바탕으로 전 과정을 직접 재구현.

### 핵심 설계

- **단일 Transformer 인코더**만 사용 (이전 연구들의 다단계/다중 인코더 구조를 단순화)
- 스펙: **6층, 8헤드, d_model=1024, d_ff=4096**, Pre-LN, GELU
- 입력 구성: `컨텍스트(C=10프레임) + 전이구간(M=5~30프레임, 0으로 채움) + 목표 키프레임(1프레임)`
- **손실**: 전체 시퀀스에 대한 단일 L1 (마스킹된 gap 구간만이 아니라 전체)
- 학습 시 M(가림 길이)을 매번 [5,30] 균일 무작위로 뽑음(RMIB의 원래 커리큘럼 방식을 SILK가 단순화한 것)
- **위치 인코딩**: 목표 키프레임을 기준(상대위치 0)으로 하는 학습형 임베딩 — RMIB의 time-to-arrival(ztta) 설계와 개념적으로 동일. 이 설계를 정확히 재현하지 않으면(예: 단순 절대 위치 임베딩) **목표/전이 구간의 위치 정체성이 M에 따라 충돌하는 confound 버그**가 생긴다는 걸 프로젝트 초기에 직접 발견·수정함 (이 수정으로 학습 수렴 속도 약 10배 개선을 확인).

### 프로젝트에서의 활용

SILK 구조를 **손 관절 회전 시퀀스**에 그대로 적용해 baseline을 구성했고, 이후 이 백본을 출발점 삼아 서로 다른 방향(모델 확장, 손실 함수 변형, 다중 키프레임, diffusion/flow matching 재구성)으로 실험을 확장했다.

## 3. Hand Motion In-betweening 태스크

### 왜 손이 특수한가

기존 motion in-betweening 연구는 **전신 동작**을 다룬다. 걷기처럼 몸 전체 위치(root)가 시간에 따라 크게 이동하는 경우가 많아, 시작·끝 자세만 봐도 "무슨 일이 일어났는지"에 대한 강한 단서가 있다.

**손은 근본적으로 다른 구조다**: 손목(root)을 기준으로 정규화하기 때문에, **"손이 벌어졌다가 다시 오므려진" 것과 "아무 일도 없었던 것"이 시작·끝 관측만으로는 구분이 안 되는 경우가 많다.** 이는 문헌상 **"multimodal ambiguity"**로 알려진 문제이며, 결정적(deterministic) 회귀 모델은 이런 상황에서 손실을 최소화하려고 "가장 안전한 답(정지)"으로 수렴하는 경향이 있다.

### 문제 설정

```
[컨텍스트 10프레임(관측)] + [gap 5~30프레임(예측 대상)] + [목표 키프레임 1개(관측)]
```

- **입력 표현**: 6D 회전(Zhou et al. Gram-Schmidt 방식), 손가락 15관절 × 6 = **90차원**, 손목 제외
- **응용 프레이밍**: 애니메이터가 배치한 키프레임을 채우는 원래 맥락이 아니라, **손 추적이 일시적으로 끊긴(occlusion) 구간을 복원**하는 문제로 재정의 — 이 프레이밍 하에서는 "정답을 미리 안다"는 가정 자체가 성립하지 않으므로, 평가 시 gap 구간의 정보가 조건에 새어 들어가지 않도록 하는 것이 특히 중요함(4, 5절 참고)

### 손 특유의 함정과 대응

| 함정 | 대응 |
|---|---|
| 6D 회전 → 실제 관절 위치 변환 시 컨벤션(행/열) 오류 위험 | 공식 소스코드(`pose_datasets_lmdb.py`) 직접 확인으로 **행(row) 기준**임을 100% 확정 |
| 왼손/오른손 좌표계 불일치 | `diag(1,-1,-1)` conjugation으로 오른손(WiLoR) 컨벤션에 통일, 공식 메커니즘과 정확히 일치 검증 완료 |
| 시작·끝이 비슷하면 모델이 "정지"로 수렴 | 다중 키프레임 조건화(세그먼트 중간점 노출), diffusion/flow matching 기반 생성형 모델 시도 |

## 4. How2Sign 데이터셋

### 출처

**SignSparK**(ECCV 2026, huggingface.co/datasets/LionelLow/SignSparK_data)가 CSL-Daily/How2Sign/BOBSL 세 코퍼스를 SMPL-X/MANO 회전 파라미터로 가공해 배포한 데이터 중 **How2Sign(미국 수어, 영어 대응)만 사용**. CSL-Daily는 저자가 공지한 미해결 한손(one-handed) 회전 버그가 있어 제외, BOBSL은 스코프상 미사용.

**중요**: 손 관절 회전값(SMPL-X/MANO 피팅) 자체는 SignSparK가 직접 추출한 것이 아니라, **선행 연구의 단일 시점(single-view) 피팅 기법으로 미리 만들어진 결과를 재사용**한 것으로 SignSparK 논문 본문에 명시돼 있다. SignSparK 자체의 기여는 (1) 수어 세그먼트 경계를 자동 탐지하는 **FAST** 모델과 (2) 그 경계를 키프레임 삼아 중간 동작을 합성하는 **Conditional Flow Matching 생성 모델**이다.

### 스키마

npz 클립당: `language`, `translation`, `gloss`, `segment`(프레임별 라벨), `left_features`(T,90), `right_features`(T,90), `body_features`(T,126), `face_features`(T,56).

- **90차원 = 15개 MANO 손가락 관절 × 6D 회전** (손목 제외 — 손목 회전은 `body_features`에 별도)
- **`segment`**: `0`=수어 아님, `1`=수어 진행 중, `2`=수어 시작 — 공식 소스로 확정된 값
- 관절 순서: `index → middle → pinky → ring → thumb` (frankmocap 공식 문서로 검증)

### 규모

- 원본: train 29,630 클립 / dev 1,650 / test 2,183
- 왼손·오른손 분리 시퀀스 기준: train 약 5.9만 / dev 3,300 / test 4,366
- stride=5 기반 조밀 윈도우 인덱스(팀 공용, offset을 좁혀 데이터를 늘리는 SILK 논문 방식): **train 약 163만 개 윈도우**

### 공식 전처리 로직에서 확인된 사실 (자체 소스코드 확인)

- **6D→행렬 변환은 행(row) 기준** Gram-Schmidt (공식 소스 주석으로 확정)
- **왼손 flip**은 `diag(1,-1,-1)` conjugation을 통한 공식 지원 메커니즘 (`flip_left_hand` 플래그, 기본은 꺼져 있으나 명시적으로 켜서 사용)
- **원래 SignSparK 태스크는 이 프로젝트보다 훨씬 풍부함**: 클립 전체(최대 224프레임)에 걸쳐 각 수어 세그먼트마다 시작/중간/끝 키프레임을 준다 (`generate_keyframes`/`_segment_bounds`). SILK와의 구조적 통일을 위해 "컨텍스트+목표 1개"로 단순화했고, 일부 실험에서 세그먼트 중간점을 보너스 조건으로 부분 복원했다 — **SignSparK 원 레시피의 완전한 재현이 아니라 의도적 단순화**임을 한계로 명시.

### 알려진 데이터 품질 한계

How2Sign의 SMPL-X 손 피팅은 **단안(monocular) 카메라 기반 단일 프레임 초기화**를 사용해, 빠른 손동작 구간에서 부정확해지는 경향이 있다(2026년 관련 논문으로 독립 확인). 회전 변화가 극단적으로 큰 일부 구간에서 관찰된 부자연스러운 손 모양은, 코드 검증(관절 순서·FK·6D 컨벤션 전부 정상) 결과 **모델의 결함이 아니라 이 데이터 자체의 알려진 한계**로 확인됨.

## 5. 평가 프로토콜

- **split**: train(학습) / dev(개인 검증) / test(최종 비교)
- **평가 지점**: 가림 길이 T = 5, 10, 20, 30
- **지표**:
  - **L2Q**: 부호보정 쿼터니언 L2 거리(더블 커버 문제 처리)
  - **L2P**: MANO forward kinematics로 복원한 관절 위치 오차
  - **NPSS**: FFT 기반 파워스펙트럼 유사도(움직임의 리듬/자연스러움)

**패턴**: 다중 키프레임 조건화는 DDPM 1→2번 실험에서 개선 확인(위 Two-stage 계열과 상반된 결과, 8절 참고). 속도 손실은 이 계열에서도 역효과. DDPM에서 Flow Matching으로 생성 프레임워크 자체를 전환한 것이 가장 큰 개선을 가져옴 — SignSparK 원 논문 자체가 Flow Matching을 사용한다는 점과도 방법론적으로 부합.

**주의**: 빠른 표본(n=3,840) 평가는 실제보다 낙관적인 수치였음이 test set 전체 재평가로 확인됨 — 이후 비교는 전체 평가 수치를 기준으로 함.


## 7. 최종 모델 선정 — exp06

### 선정 근거

**exp06(SILK 원 논문 크기, 76M 파라미터, 결정적 회귀)이 L2Q·L2P·NPSS 세 지표, T=5/10/20/30 전 구간에서 가장 낮은(좋은) 오차를 기록**했다. 전체 test set 기준 재평가에서도 다른 계열과의 격차가 유지·확대되어, 5절의 주의사항을 감안해도 결론이 뒤집힐 가능성은 낮다고 판단.

### 해석

- **모델 크기가 이 태스크에서 뚜렷한 성능 요인**임을 3M→19M→76M 스케일업 실험이 일관되게 보여줌. 다만 19M(exp01)과 76M(exp06)의 격차가 3M→19M 구간만큼 크지 않아, **모델 크기를 1/4 수준으로 줄여도 성능이 상당 부분 방어됨** — 실용적 배포 시 경량 모델(19M)이 합리적 대안이 될 수 있음을 시사
- 보조 손실(다양성/속도) 추가는 서로 다른 접근에서 **독립적으로 재현된 역효과** — 신뢰도 높은 부정적 결과로 보고 가치 있음
- **다중 키프레임 조건화의 효과는 일관되지 않음**: diffusion/flow 계열에서는 개선을, SILK Two-stage 계열에서는 악화를 보여 — "다중 키프레임이 최선의 조건화 방식"이라고 일반화할 근거는 아직 부족하며, 구현 방식·백본과의 상호작용을 더 살펴볼 필요가 있음(8절)
- **정확도 지표(L2Q/L2P/NPSS)는 "정답과의 거리"를 재는 방식이라, 결정적 회귀 모델의 "안전한 평균" 예측에 상대적으로 유리하게 작용할 수 있음.** Diffusion/flow 계열은 애초에 이 지표들이 잘 포착하지 못하는 문제(다양성, multimodal ambiguity 완화)를 겨냥해 설계됐다는 점에서, **정확도 1위가 아니라는 결과가 방법론의 실패를 의미하지는 않음** — 정성적 시각화를 통한 보완적 평가가 필요하다는 점을 한계 및 향후 과제로 명시


## 8. 시사점

### 손 특화 in-betweening의 구조적 특수성 확인

몸 전체 동작과 달리, 손은 root(손목) 고정 정규화로 인해 "정지"와 "왕복 동작"을 시작·끝만으로 구분하기 어려운 multimodal ambiguity가 두드러진다는 것을 실증적으로 확인함. 이는 향후 손 동작 생성 연구에서 몸 전체 동작 연구의 방법론을 그대로 가져오기보다, 손 특유의 모호성 해소 메커니즘이 별도로 필요함을 시사.

### 다중 키프레임 조건화 — 엇갈린 결과, 추가 검증 필요

세그먼트 기반 다중 키프레임 조건화가 diffusion/flow 계열에서는 긍정적이었지만 SILK Two-stage 계열에서는 오히려 소폭 악화됐다. 같은 아이디어(원 데이터셋의 `segment` 구조 정보 활용)가 **생성 프레임워크(결정적 회귀 vs 생성형)에 따라 다르게 작용할 수 있다**는 신호로 해석되며, 단정적 결론을 내리기보다 추가적인 통제 실험(같은 백본에서 조건화만 켜고 끄는 ablation)이 필요함.

### 모델 크기 대비 효율의 중요성

76M(exp06)과 19M(exp01)의 성능 격차가 3M→19M 구간보다 작다는 점은, 이 태스크에서 **일정 규모 이상부터는 수확체감(diminishing returns)**이 나타날 수 있음을 시사 — 향후 연구에서 순수 파라미터 확장보다 구조적 효율 개선이 더 생산적일 수 있음.

### 생성 프레임워크 선택의 중요성

같은 조건화·백본에서 DDPM보다 Flow Matching이 뚜렷하게 우수했다는 결과는, SignSparK 원 논문이 애초에 Flow Matching을 택한 이유와 방법론적으로 부합한다. 생성형 모델을 적용할 때 "diffusion이냐 아니냐"보다 **구체적으로 어떤 노이즈-데이터 경로·샘플링 방식을 쓰느냐**가 성능에 실질적 영향을 준다는 것을 재확인.

### "정확도" 이외의 평가축 필요성

결정적 회귀가 거리 기반 지표에서 앞서는 경향은, 이런 지표들이 생성형 모델의 강점(다양성, 실제 배포 상황에서의 강건성)을 온전히 포착하지 못할 수 있음을 시사한다. 향후 연구·발표에서 정량 지표와 정성적 평가(사람이 직접 보는 자연스러움, 다양성)를 함께 제시하는 것이 이 분야 전체에 필요한 방향일 수 있다.
